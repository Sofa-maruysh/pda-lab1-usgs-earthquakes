## Цель и метод

Цель — построить воспроизводимый ETL-процесс и выполнить не менее пяти разных запросов для агрегации. Мы обращаемся к `GET /fdsnws/event/1/query` с параметрами `format=geojson`, `eventtype=earthquake`, датами и нижней границей магнитуды. Это прямой сбор с веб-ресурса, а не готовый датасет. Сервис поддерживает `limit` до 20 000 и `offset`; поэтому код обходит страницы. По [документации USGS](https://earthquake.usgs.gov/fdsnws/event/1/1) время без часового пояса трактуется как UTC, а `endtime` включительно. В программе период задан как `[start, end)`, поэтому из конечной полуночи вычитается одна миллисекунда.

В SQLite создана таблица `earthquakes`. Первичный ключ — ID события USGS. Сохраняются время события и обновления, магнитуда, глубина, координаты, место, сеть, статус, флаг tsunami, значимость и ссылка на запись. Догрузка реализована через SQLite `INSERT ... ON CONFLICT DO UPDATE`; запись меняется только при более новом `updated_ms`. Повторный запрос того же периода не удваивает данные.

Агрегации сделаны двумя независимыми способами: SQLAlchemy строит SQL-запросы к SQLite, а pandas загружает строки из БД и группирует их в памяти. У обоих способов одинаковые границы диапазонов: магнитуды `<3`, `3–<4`, `4–<5`, `5–<6`, `≥6`; глубины `<70`, `70–<300`, `≥300` км. События без глубины исключаются только из группировки по глубине.

## Воспроизводимый эксперимент

Дата проверки: 2 октября 2026 года. Период событий: **1–14 января 2025 года UTC**, магнитуда **≥2,5**. Команды:

```powershell
python usgs_lab1.py sync --start 2025-01-01 --end 2025-01-08 --min-magnitude 2.5
python usgs_lab1.py sync --start 2025-01-01 --end 2025-01-08 --min-magnitude 2.5
python usgs_lab1.py sync --start 2025-01-08 --end 2025-01-15 --min-magnitude 2.5
python usgs_lab1.py analyze
```

| Запуск | Получено из API | Добавлено или обновлено | Строк в БД |
|---|---:|---:|---:|
| 1–7 января, первый запуск | 585 | 585 | 585 |
| 1–7 января, повтор | 585 | 0 | 585 |
| 8–14 января, догрузка | 516 | 516 | 1101 |

Значения каталога USGS могут уточняться после проверки; при повторении опыта итоговые числа могут отличаться. Локальная база данных и CSV не включены в репозиторий, чтобы их можно было пересоздать из источника.

## Результаты шести агрегаций

1. **По дням.** Получено 14 строк. Больше всего событий зарегистрировано 7 января: **107**; максимальная магнитуда в этот день — **7,1**. Запрос показывает изменение активности во времени.
2. **По магнитуде.** Получено пять групп: `<3` — **225**, `3–<4` — **138**, `4–<5` — **659**, `5–<6` — **73**, `≥6` — **6** событий. Наибольшая группа — `4–<5`.
3. **По глубине.** Мелких событий — **891**, промежуточных — **169**, глубоких — **41**. Средняя магнитуда в этих группах: **3,94**, **4,09** и **4,42** соответственно.
4. **По сетям.** Получено 11 групп. В каталоге больше всего записей с кодом сети `us` — **894**; далее `ak` — **50**, `pr` — **46**, `nc` — **42**. Это распределение по источнику записи, не географическая карта землетрясений.
5. **По часам UTC.** Получено 24 группы. Наиболее заполненный час — **01:00–01:59 UTC**, **67** событий. Это описательная частота в выбранном двухнедельном интервале, а не закономерность времени возникновения землетрясений.
6. **По флагу tsunami.** `tsunami=0`: **1099** событий, средняя магнитуда **3,98**, средняя значимость **258,07**. `tsunami=1`: **2** события, средняя магнитуда **5,73**, средняя значимость **749**. Малый размер второй группы не позволяет делать общий вывод о риске цунами.

Для каждой агрегации в `results/` создаются два CSV. На реальной базе из **1101** событий результаты pandas и SQLAlchemy совпали по группам и количествам; расхождение чисел с плавающей точкой было менее `1e-8`. Автоматический тест дополнительно проверяет обновление записи, появление новой записи и совпадение всех шести пар агрегатов на контролируемом наборе.

## Вывод

Данные USGS собраны напрямую через API и сохранены в SQLite. Первичный ключ и upsert обеспечивают догрузку без дублей. Шесть независимых аналитических запросов реализованы и сверены в pandas и SQLAlchemy. Ограничение анализа: данные каталога могут исправляться, а выборка ограничена датами и минимальной магнитудой; поэтому выводы относятся только к указанной выборке.
