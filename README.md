# Сбор и агрегация данных о землетрясениях

Лабораторная работа №1. Марюшкина Софья, Чуева Арина — поток 1.3.

В работе реализованы сбор данных с [USGS Earthquake Catalog](https://earthquake.usgs.gov/fdsnws/event/1/), их хранение в SQLite с возможностью догрузки и шесть запросов для агрегации. Сбор выполняется библиотекой Scrapy через API USGS. Для работы с базой используется SQLAlchemy, для обработки данных — pandas.

**Отчёт по лабораторной работе:** [lab1_usgs.ipynb](lab1_usgs.ipynb). Блокнот содержит все шесть разделов установленной структуры: название, цель и задачи, описание входных данных, этапы с кодом и примерами выполнения, результаты и выводы. Результаты выполнения сохранены внутри файла. Блокнот выполняется из корня проекта с установленными зависимостями; для воспроизводимого опыта каждый раз создаётся новая SQLite-база в `data/report_runs/`.

## Собираемые данные

Одна строка таблицы `earthquakes` соответствует одному событию USGS.

| Поле | Описание |
|---|---|
| `event_id` | Уникальный ID события USGS, первичный ключ |
| `occurred_at` | Дата и время события в UTC |
| `updated_ms` | Время последнего обновления записи в USGS, миллисекунды Unix |
| `magnitude` | Магнитуда |
| `depth_km` | Глубина, км |
| `latitude`, `longitude` | Координаты |
| `place` | Описание места |
| `region` | Географическая подпись из `place`, если её можно выделить |
| `network` | Код сети, предоставившей запись |
| `status` | Статус проверки события |
| `tsunami` | Флаг tsunami из каталога USGS |
| `significance` | Показатель значимости события USGS |
| `url` | Ссылка на событие |

## Сбор и догрузка

Scrapy запрашивает данные в формате GeoJSON и обрабатывает ответ: свойства события и координаты преобразуются в поля таблицы. Большая выборка загружается по страницам с параметрами `limit` и `offset`. Записи без ID, магнитуды, времени или координат пропускаются и учитываются в статистике загрузки.

По умолчанию выбран период **1–14 января 2025 года**, магнитуда **от 2,5**. Начало периода включено, конец не включён; все даты относятся к UTC.

Наличие событий проверяется пакетами по 500 ID: один `SELECT ... WHERE event_id IN (...)` на пакет. Для новых и более свежих записей выполняется пакетный `INSERT ... ON CONFLICT DO UPDATE`; сравнение `updated_ms` в SQL защищает от перезаписи старой версией. Отдельного поиска в базе для каждой строки нет. Повторная загрузка не создаёт дубликатов. Для догрузки указывается следующий период.

`region` извлекается из описания USGS `place`: для `88 km NE of Hirara, Japan` сохраняется `Japan`, для готовой географической подписи `Mid-Indian Ridge` — сама подпись. Это может быть страна, штат, территория или природный район; поле не является строгим справочником стран и не заменяет исходное `place`. Если есть только расстояние до населённого пункта без региона или название конкретного землетрясения, сохраняется NULL. Дополнительные географические сведения не угадываются.

При открытии ранее созданной базы добавляется только отсутствующий столбец `region`, а его значения заполняются пакетно из сохранённого `place`. Исходные события, их ID и остальные поля сохраняются.

## Агрегация данных

В `analysis.py` каждый запрос реализован двумя способами: pandas группирует строки, прочитанные из SQLite, а SQLAlchemy формирует SQL-запрос, который выполняется в базе.

| № | Группировка | Рассчитываемые показатели |
|---|---|---|
| 1 | День UTC | Количество событий, средняя и максимальная магнитуда |
| 2 | Диапазон магнитуды | Количество событий, средняя глубина |
| 3 | Диапазон глубины | Количество событий, средняя магнитуда |
| 4 | Сеть каталога | Количество событий, средняя и максимальная магнитуда |
| 5 | Час UTC | Количество событий, средняя магнитуда; сортировка по количеству по убыванию |
| 6 | Флаг tsunami | Количество событий, средняя магнитуда и значимость |

Диапазоны магнитуды: `<3`, `3–<4`, `4–<5`, `5–<6`, `≥6`. Диапазоны глубины: `<70`, `70–<300`, `≥300` км. Неизвестная глубина исключается из группировки по глубине.

**Обоснование глубин.** Классификация взята из статьи William Spence, Stuart A. Sipkin и George L. Choy, *Determining the Depth of an Earthquake*, *Earthquakes and Volcanoes*, vol. 21, no. 1 (1989), опубликованной [USGS](https://www.usgs.gov/programs/earthquake-hazards/determining-depth-earthquake). В ней выделены shallow (0–70 км), intermediate (70–300 км), deep (300–700 км). В работе использованы названия «мелкофокусные», «промежуточные» и «глубокофокусные». Чтобы границы не пересекались, значение ровно 70 км отнесено ко второй группе, ровно 300 км — к третьей. Третья группа в коде не ограничена сверху, чтобы не отбрасывать значения каталога. Отрицательные значения глубины, которые могут встречаться в USGS из-за выбранной поверхности отсчёта, остаются в первой группе; их смысл объяснён в [FAQ USGS о нулевой и отрицательной глубине](https://www.usgs.gov/faqs/what-does-it-mean-earthquake-occurred-a-depth-0-km-how-can-earthquake-have-a-negative-depth).

В запросе №5 на первом месте находится час с наибольшим числом событий. При равном количестве часы расположены по возрастанию; порядок одинаков в pandas и SQLAlchemy.

```bash
python analysis.py
```

Результаты выводятся в консоль и сохраняются в 12 CSV-файлов: по два на каждый запрос. Соответствующие таблицы pandas и SQLAlchemy автоматически сравниваются с допуском `1e-8` для чисел с плавающей точкой.

## Результаты

Проверка на данных USGS от 5 октября 2026 года, период событий 1–14 января 2025 года:

| Этап | Получено | Добавлено | Всего строк в базе |
|---|---:|---:|---:|
| Загрузка 1–7 января | 585 | 585 | 585 |
| Повтор 1–7 января | 585 | 0 | 585 |
| Догрузка 8–14 января | 516 | 516 | 1101 |

По результатам агрегаций:

- Больше всего событий за день: **107**, 7 января. Максимальная магнитуда этого дня — **7,1**.
- Самая многочисленная группа по магнитуде: **4–<5**, **659** событий.
- По глубине: **891** событие менее 70 км, **169** — от 70 до 300 км, **41** — от 300 км.
- Больше всего записей предоставила сеть `us`: **894**.
- Наиболее частый час UTC в выборке — **01:00–01:59**, **67** событий.
- Флаг `tsunami=1` установлен у **2** событий, `tsunami=0` — у **1099**. Этот флаг сам по себе не подтверждает возникновение цунами.

Результаты всех шести запросов совпали в pandas и SQLAlchemy. Данные сохранены в SQLite, повторная загрузка не создаёт дубли, догрузка увеличивает число записей. Выводы относятся к выбранному периоду и порогу магнитуды; каталог USGS может уточняться, поэтому результаты последующих загрузок могут отличаться.

При повторной проверке 19 октября 2026 года выполнены все 16 ячеек отчёта: результаты загрузки и шести агрегаций подтверждены. Регион выделен у 1100 из 1101 события; у оставшегося события сохранён NULL. Проверки в `tests/test_lab.py` дополнительно подтверждают пакетный поиск, сохранность старой схемы при добавлении столбца, обработку версий, границы глубины и порядок пятого запроса.
